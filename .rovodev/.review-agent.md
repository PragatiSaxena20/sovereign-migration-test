# Custom Code Review Instructions for Sovereign

This document provides guidance for AI code reviewers to identify critical coding standards and bug patterns specific to the Sovereign codebase (an Envoy Proxy control-plane).

---

## Coding Standard: Lazy Import to Avoid Circular Dependencies

**Description**: Import `sovereign.configuration` lazily inside functions rather than at module level to prevent circular import errors. This is critical because `sovereign.configuration` loads entry points and loaders during initialization, which may themselves import modules that depend on configuration.

**Reference**: 
- Commit: `677161a7baab223bb9ea706bbea7818e8667ded0`
- File: `src/sovereign/v2/logging.py`

**Why it matters**: Circular imports cause runtime failures during application startup. Lazy imports ensure modules can be safely imported from anywhere, including during configuration initialization.

### ✅ Good Example
```python
def capture_exception(exc: BaseException) -> None:
    """
    sovereign.configuration is imported lazily to avoid a circular import:
    this module is safe to import from anywhere (including loaders loaded
    during configuration initialisation), whereas sovereign.configuration
    is not fully initialised at that point.
    """
    from sovereign.configuration import config

    if config.sentry_dsn.get_secret_value():
        try:
            mod = importlib.import_module("sentry_sdk")
            mod.capture_exception(exc)
        except ImportError:
            pass
```

### ❌ Bad Example
```python
from sovereign.configuration import config

def capture_exception(exc: BaseException) -> None:
    # This causes circular import if this module is imported during config initialization
    if config.sentry_dsn.get_secret_value():
        try:
            mod = importlib.import_module("sentry_sdk")
            mod.capture_exception(exc)
        except ImportError:
            pass
```

## Coding Standard: Singleton Pattern with Module-Level Caching

**Description**: Cache singleton instances (data stores, queues, repositories) in module-level variables to avoid recreating expensive resources (e.g., boto3 clients, database connections) on every request. Always check if the singleton exists before creating it.

**Reference**: 
- Commit: `7e64298aca2252dcc8ec5d4496b016e711c1d2b2`
- File: `src/sovereign/v2/data/utils.py`

**Why it matters**: Creating new instances of expensive resources (like boto3 SQS clients) on every web request causes severe performance degradation and resource exhaustion.

### ✅ Good Example
```python
_queue: QueueProtocol | None = None

def get_queue() -> QueueProtocol:
    global _queue

    if not _queue:
        entry_points = EntryPointLoader("queues")

        for entry_point in entry_points.groups["queues"]:
            if entry_point.name == config.worker_v2_queue_provider:
                _queue = entry_point.load()()
                break

        if not _queue:
            raise ValueError(
                f"Queue '{config.worker_v2_queue_provider}' not found in entry points"
            )

    return _queue
```

### ❌ Bad Example
```python
def get_queue() -> QueueProtocol:
    # Creates a new SqsQueue/boto3 client on every call - severe performance issue
    entry_points = EntryPointLoader("queues")

    for entry_point in entry_points.groups["queues"]:
        if entry_point.name == config.worker_v2_queue_provider:
            return entry_point.load()()

    raise ValueError(
        f"Queue '{config.worker_v2_queue_provider}' not found in entry points"
    )
```

## Coding Standard: Thread-Safe Reference Counting with Locks

**Description**: When implementing reference counting for shared resources (like process pools), always protect both the counter increment/decrement AND the resource creation/cleanup with the same lock to prevent race conditions.

**Reference**: 
- Commit: `4879d3eb62d0336b1f83d07753c787f62dd613b5`
- File: `src/sovereign/v2/web.py`

**Why it matters**: Without proper locking, race conditions can cause incorrect reference counts, leading to premature resource cleanup or resource leaks in multi-threaded environments.

### ✅ Good Example
```python
_inline_render_pool: ProcessPoolExecutor | None = None
_inline_render_pool_lock = threading.Lock()
_inline_render_count: int = 0

async def wait_for_discovery_response(...):
    global _inline_render_count
    pool = _get_inline_render_pool()
    with _inline_render_pool_lock:
        _inline_render_count += 1
    try:
        response = await asyncio.get_running_loop().run_in_executor(pool, ...)
    finally:
        with _inline_render_pool_lock:
            _inline_render_count -= 1
            if _inline_render_count == 0:
                _shutdown_inline_render_pool()
```

### ❌ Bad Example
```python
_inline_render_pool: ProcessPoolExecutor | None = None
_inline_render_pool_lock = threading.Lock()
_inline_render_count: int = 0

async def wait_for_discovery_response(...):
    global _inline_render_count
    pool = _get_inline_render_pool()
    _inline_render_count += 1  # Race condition: not protected by lock
    try:
        response = await asyncio.get_running_loop().run_in_executor(pool, ...)
    finally:
        _inline_render_count -= 1  # Race condition: not protected by lock
        if _inline_render_count == 0:
            _shutdown_inline_render_pool()
```

## Bug Pattern: Stale Lock Not Cleared After State Changes

**Description**: When using locks/flags to prevent duplicate work (e.g., `rendering_started_at`), always explicitly clear the lock after successful completion as a defense-in-depth measure. Don't rely solely on implicit clearing through data serialization, as some implementations may omit `None` fields.

**Reference**: 
- Commit: `21816a7d5ccebc798b37c8ddd91c513493f39020`
- Commit: `f418210a76fd1d80736aef39a39616304c596122`
- File: `src/sovereign/v2/jobs/render_discovery_job.py`

**Why it matters**: Stale locks block subsequent operations for extended periods (up to 600 seconds in this codebase), causing service degradation. This has occurred multiple times in the git history.

### ✅ Good Example
```python
def render_discovery_response(...):
    def clear_rendering_started_at_best_effort() -> None:
        try:
            discovery_entry_repository.clear_rendering_started_at(request_hash)
        except Exception as clear_error:
            logger.warning("Failed to clear rendering_started_at", clear_error=clear_error)

    try:
        response = render_template_to_response(...)
        if response is None:
            # Clear the lock so other jobs can try rendering
            clear_rendering_started_at_best_effort()
            return False

        if not discovery_entry_repository.save(...):
            # Clear the lock since save failed
            clear_rendering_started_at_best_effort()
            return False

        # Explicitly clear as defense-in-depth - save() may not clear if
        # DataStore implementation omits None fields from serialization
        clear_rendering_started_at_best_effort()
        return True
    except Exception:
        clear_rendering_started_at_best_effort()
        raise
```

### ❌ Bad Example
```python
def render_discovery_response(...):
    try:
        response = render_template_to_response(...)
        if response is None:
            # BUG: Lock not cleared, blocks subsequent renders for 600s
            return False

        if not discovery_entry_repository.save(...):
            # BUG: Lock not cleared on save failure
            return False

        # BUG: Assumes save() cleared the lock, but some DataStore implementations
        # may omit None fields, leaving stale lock
        return True
    except Exception:
        # BUG: Lock not cleared on exception
        raise
```

## Bug Pattern: Using set_property Instead of set_property_if_exists

**Description**: Use `set_property_if_exists()` instead of `set_property()` when updating properties on existing records. `set_property()` creates a new record with only that property set (others are `None`) if the record doesn't exist, which can cause data loss or unexpected behavior.

**Reference**: 
- Commit: `3d6c278d7aab4c83acbb35b00f53eee429d4528f`
- File: `src/sovereign/v2/data/repositories.py`

**Why it matters**: Using `set_property()` for updates can accidentally create partial records, leading to data integrity issues and application errors when other code expects complete records.

### ✅ Good Example
```python
@stats.timed("v2.repository.discovery_entry.update_last_requested_at_ms")
def update_last_requested_at(self, request_hash: str) -> bool:
    # Only updates if the entry exists - won't create a partial entry
    return self.data_store.set_property_if_exists(
        DataType.DiscoveryEntry, request_hash, "last_requested_at", int(time.time())
    )

@stats.timed("v2.repository.discovery_entry.clear_rendering_started_at_ms")
def clear_rendering_started_at(self, request_hash: str) -> bool:
    # Only clears if the entry exists - won't create a partial entry
    return self.data_store.set_property_if_exists(
        DataType.DiscoveryEntry, request_hash, "rendering_started_at", None
    )
```

### ❌ Bad Example
```python
@stats.timed("v2.repository.discovery_entry.update_last_requested_at_ms")
def update_last_requested_at(self, request_hash: str) -> bool:
    # BUG: Creates a new DiscoveryEntry with ONLY last_requested_at set
    # if the entry doesn't exist (other fields like request, template are None)
    return self.data_store.set_property(
        DataType.DiscoveryEntry, request_hash, "last_requested_at", int(time.time())
    )

@stats.timed("v2.repository.discovery_entry.clear_rendering_started_at_ms")
def clear_rendering_started_at(self, request_hash: str) -> bool:
    # BUG: Creates a partial entry if it doesn't exist
    return self.data_store.set_property(
        DataType.DiscoveryEntry, request_hash, "rendering_started_at", None
    )
```

## Bug Pattern: Missing None Handling in Optional Timestamp Fields

**Description**: When working with timestamp fields that can be `None` (e.g., `last_requested_at`, `last_rendered_at`, `rendering_started_at`), ensure the type annotation allows `None` and handle `None` values in comparisons and logic.

**Reference**: 
- Commit: `552e0fa162b8845cd8dc6e126aea1225bb168501`
- File: `src/sovereign/v2/types.py`

**Why it matters**: Missing `None` handling causes runtime type errors and crashes when optional fields are actually `None`, especially during initial record creation or after certain operations.

### ✅ Good Example
```python
class DiscoveryEntry(pydantic.BaseModel):
    request_hash: str
    template: str
    request: DiscoveryRequest
    response: DiscoveryResponse | None
    last_rendered_at: int | None = None
    rendering_started_at: int | None = None
    last_requested_at: int | None  # Allows None for new entries

def process_entry(entry: DiscoveryEntry):
    # Properly handles None case
    if entry.last_requested_at is not None:
        age = int(time.time()) - entry.last_requested_at
        if age > MAX_AGE:
            prune_entry(entry)
```

### ❌ Bad Example
```python
class DiscoveryEntry(pydantic.BaseModel):
    request_hash: str
    template: str
    request: DiscoveryRequest
    response: DiscoveryResponse | None
    last_rendered_at: int | None = None
    rendering_started_at: int | None = None
    last_requested_at: int  # BUG: Doesn't allow None, but can be None in practice

def process_entry(entry: DiscoveryEntry):
    # BUG: Crashes with TypeError if last_requested_at is None
    age = int(time.time()) - entry.last_requested_at
    if age > MAX_AGE:
        prune_entry(entry)
```
